## D2 · 外部数据源走适配层，不直连

**决策**：所有外部取数收敛到 `core/paper_agent/sources.py`，业务代码不直接发网络请求。

**职责边界（严格）**：
- **只做"取数 + 字段映射 + 值分类"，不做语义清洗**。哪些行能进入计算、如何补缺、
  如何标记异常，全部由 P2 决定并留痕。
- **不产生任何数值**：数值只来自外部数据集原样搬运（归一化仅为格式统一）。

**理由**：换数据源时只改适配层；且"取数"与"判断"分离后，
证据链上能明确区分「外部来的」与「我们算的」。

## D3 · 双腿（文献 + 数据）对接，**假设已被实测否证**

**原设计假设**：文献腿与数据腿的论文 DOI 应有较高重合。

**🔴 实测否证（这是本项目最重要的一条修正，务必保留）**：

```
文献腿（4 检索式 × 2 来源） 373 篇  ∩  OBELiX 数据腿 222 篇  =  8 篇（2.1%）
```

**原因**：文献腿给的是**话题全景**（综述与近年高影响论文），
数据腿是**一个特定实测数据集的来源论文**；两者天然只有少量重叠。

**因此 `anomaly.py` 的异常规则据此修正**：
- **"对接率低"不是异常**（正常就低）→ 只作为指标报告（`join_rate_*`）
- **"两腿交集为零"才是异常** → 说明检索式完全跑偏，需要人裁决

**教训**：设计文档里的"应该会…"必须实测验证。本条若不验，
异常规则会长期误报，最终没人看告警。

## D4 · 判断 = 生成检索式 + 判定相关对象（**档 3：可插拔判断器**）

**决策**：拆成两件事——「生成检索式」与「判定哪些对象相关」。
采用**档 3（可插拔）**实现，即 `core/paper_agent/judge.py`。

**关键约束**：判断是本项目中**唯一**允许模型参与的环节，
产出物一律为 **judgment 级**对象：
- 影响流程走向
- **不得进入结论**
- 必须**全额留痕**（含被排除项与理由）

**理由**：把"模型参与了哪一步"钉死成一个可审计的点。
其余环节保持确定性，才能承诺逐字节可复现。

## D5 · 证据账本 + 结论‑证据绑定（三级信任）

**决策**：`core/paper_agent/provenance.py` 以 mike 双工作流
（materials + research）的全部证据种类为基底，吸收 novus 的**三级信任模型**：

| 级别 | 含义 | 能否进结论 |
|---|---|---|
| `fact` | 外部可核验的客观事实 | ✅ |
| `judgment` | 模型判断（含被排除项与理由） | ❌ 仅影响流程走向 |
| （派生） | 由 fact 计算得到 | ✅ 需绑定来源 fact |

**要求**：每条结论必须绑定证据；引文格式化统一由本模块负责，
不允许各步各写一套。

## D6 · 冻结输入快照（复现契约的载体）

**决策**：`core/paper_agent/snapshot.py`。模型筛选结果一旦产生，**立即冻结**为输入快照；
此后的复算、验证、重新出报告**全部针对该快照**。

**承诺边界（必须照抄这个措辞）**：
- ✅ 承诺"**从快照到结论**"逐字节可复现
- ❌ **不承诺**"模型这次筛了什么"跨次一致

**理由**：后者依赖模型非确定性，承诺不了就不承诺。
把不可承诺的部分显式排除，剩下的才是可验证的工程契约。

## D7 · 异常驱动打断：四条异常码

**决策**：`core/paper_agent/anomaly.py` 定义四个异常码，
命中即**打断流程交人裁决**，不自动硬闯。

| 异常码 | 含义 | 备注 |
|---|---|---|
| `zero_hits` | 检索式零命中 | 检索式跑偏 |
| `no_leg_overlap` | **两腿交集为零** | 见 D3：交集低不算异常，为零才算 |
| `judge_hit_rate` | 判断命中率反常 | 模型自评异常 |
| `judge_self_contradiction` | 模型自相矛盾 | 同一次判断内部冲突 |

**配套**：`freezing.py` 的三段式冻结流程（`prepare()` → 会话内大模型推理产出裁决 → 固化）
即为此设计，**与 D6 快照配合**：打断时冻结的正是待判对象与规则式参考。

## D10 · 模型从哪来：会话内判断为主，标准端点为辅

**决策**：两条路径，按场景分工。

### 主路径：AGH 会话内判断（Python 不调模型）
会话里的大模型读候选 → 自行推理 → 调用插件工具把裁决写进快照。
`ModelJudge` 是该数据契约的实现。

**为什么这条路可行**（`llm.py` 里的实测排除）：
- `agh -p` / `--mode json` 打印模式 → **非交互环境下会挂起**（实测 150s 超时零输出），
  它是完整 agent 会话，不是单次问答接口；
- `agh serve model-api` → `/v1/models` 404、`POST /v1/chat/completions` 405、`/openapi.json` 404，
  源码走 `_agnes/v1/...` 命名空间，**不是** OpenAI 风格的补全路由；
  它是给人用的控制台。

→ 既然 CLI 侧拿不到稳定的补全接口，主路径就**不依赖 Python 调模型**。

### 辅助路径：`OpenAiChatClient`（会话之外的自动化）
跑对比、批处理、CI 需要标准 OpenAI 兼容端点。
不绑定厂商，由使用者通过环境变量或参数提供 `base_url` / `model` / `api_key`。
`CallableClient` 用于测试与自定义后端（注入任意函数）。

**密钥处理**：本模块**不读取、不落盘任何密钥**；
`OpenAiChatClient` 只使用调用方传入的 `api_key`。

## 附：与本次重建相关的两条补充决策（2026-10-05追查后补记）

### M4 已关闭（不做 ACP 增强通道）
原计划让前端经 ACP 通道把输入转发给 AGH。**实测发现 ACP 模式根本不装载第三方插件**
（三条启动路径分叉：`boot/default.ts:25` 把ACP 提前拦去自建一次性 Host，
而该 Host 既不传 `runtimePluginSnapshots`，又只遍历 `profile.packages` 而非 `lock.packages`）。

**关闭理由是"收益不足"，不是技术阻塞**：
插件层（`plugins/paper-agent-tools/index.mjs:153`）只是
`spawn` Python 的薄壳，**全部科研业务在 Python CLI**——
调不到插件丢的只是转接器，不是任何科研能力。
完整追查记录见 `docs/对接方案.md` §2.5。

### 确定性流水线不由 LLM 编排
P1–P5 / R1–R6 是确定性状态机，核心卖点是可复现 + 证据可溯源，
且每步真实耗时 8–12 秒。把编排权交给 LLM 只会引入不可复现性。
AGH 装不上插件这件事反过来**验证**了这个选型。
