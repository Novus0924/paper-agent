- 状态：**草案，已逐条评审确认**（10 项决定全部落定，无遗留"看情况"）
- 记录日期：2026-10-02
- 决策方式：逐分支拷问（grill-me），每项决定均记录被否决的备选方案与理由
- 适用范围：本文件是本次改造的**唯一权威决定记录**；与 `README.md` / `docs/HANDOFF.md` 冲突时以本文件为准

---

## 1. 问题诊断（为什么必须改）

对现状的独立评估结论：**它目前只是一台"带审计功能的计算器"**。

| 症状 | 证据 |
|---|---|
| 数据不是它拿的，是人喂的 | 7 行数据手工写死在 `data/conductivity_raw.csv`；P1 的检索结果与 P3 的计算**没有任何数据往来** |
| 没有任何真正的判断 | 关键词靠规则抽取，相关性靠数词频，五步顺序写死 |
| 文献层是假的 | `data/literature.json` 只有 5 张手写卡片，与计算过程无关，仅用于生成"我参考了 5 篇文献"这句话 |
| 模型层是装饰 | `python -m paper_agent.cli run-all --goal "..."` 一条命令即可跑完全流程，**全程不需要模型** |

推论：仅把 P1 换成真检索、产出仍只喂给报告，**依然是计算器**。真正的分界线是——**数据第一次自己走进来，且存在需要判断的环节**。

---

## 2. 改造目标与验收判据

### 2.1 目标
让 Agent **去真实世界取数据、做筛选判断、自己记账**，把"人工喂数据 → 程序算数"改造为"检索 → 判断 → 取数 → 计算 → 复现 → 报告"，全链路可审计。

### 2.2 成功判据（五条，全部可证伪）

| # | 判据 | 验证方式 |
|---|---|---|
| 1 | 数据不再是喂进去的 | 删除 `data/conductivity_raw.csv` 后，主线（快照）与增强线（联网）均能取得 **≥500 条**带 DOI 的真实材料数据 |
| 2 | 判断真的发生了 | 两个不同问题必须产出**不同的检索式**与**不同的论文集合** |
| 3 | 异常真的会打断 | 构造"零命中"与"命中率反常"，系统必须**停下等人裁决**，不得静默通过 |
| 4 | 三级分离真的绑上了 | 报告每句话可反查"事实"级证据；**删除模型判断记录后，报告必须生成失败** |
| 5 | 干净机器一条命令跑通主线 | 无第三方库、无网络、无 key，产出完整报告 + 审计包 |

### 2.3 反判据（防自欺）
> 把模型换回固定词频规则，如果**结论几乎不变** → 说明模型是装饰品，本次改造失败。

## 3. 设计决定（10 项）

### D1 目标能力：真实联网检索 + 相关性判断
- **决定**：检索的产出必须是**实验数据本身**，而非"参考文献清单"。
- **否决**：只做"自动生成参考文献列表"——对"计算器"问题零改善，反而更像花架子。

### D2 数据源：OBELiX
- **决定**：采用 **OBELiX**（NRC-Mila，arXiv:2502.14234，CC-BY-4.0）
  - 599 条锂固态电解质材料，**室温离子电导率为实验实测值**（S/cm）
  - **每条带原始实验论文的 DOI**（证据链第一次有真牙齿）
  - 附带空间群、晶格参数、化学式；321 条含 CIF 结构文件
  - 公开 CSV 可下载（GitHub / Kaggle），另提供 `obelix-data` Python 包（**本项目不使用**，见 D9）
  - 数据自带真实脏数据：37 条写成 `<1E-10` 上界记法、部分字段留空、"close_match"标记
- **否决**：Materials Project——其强项是计算性质（结构/热力学/带隙/弹性），**离子电导率不是标准属性**，需自行跑力场 MD / DFT，算力成本高。

### D3 结构：双腿 + DOI 对接
- **决定**：P1 拆成**两条腿**
  - **文献腿**：调 arXiv / Crossref / OpenAlex 元数据接口 → 回答"这个话题下有哪些真实论文"
  - **数据腿**：拉 OBELiX → 回答"这些材料实测电导率是多少"
  - **两腿用 DOI 对接**：检索到的论文 ↔ 该论文的实测数据 ↔ 最终结论，全程同一套 DOI 串联
- **说明**：OBELiX 是公开数据集快照，性质是"取数"而非"搜索"；文献腿承担"搜索与判断"，两者互补。

### D4 放权档位：档 3
- **决定**：
  - 检索式由**模型生成**
  - 相关性由**模型逐篇判断并给出理由**
  - 程序只做搬运与记账
- **否决**：
  - 档 1/2（模型不判断或只生成检索式）——判断为零，"计算器"问题未解
  - 档 4（连"搜够了没有、零命中怎么办"也交给模型，形成自主循环）——**推迟到第二批**。理由：循环次数由模型决定会摧毁可复现性，且难以审计。

### D5 信任模型：事实 / 判断 / 结论 三级分离
- **决定**：证据账本中的对象分三级，权限严格不同

| 级别 | 内容 | 能否进结论 | 存证要求 |
|---|---|---|---|
| **事实 fact** | OBELiX 实测数值、接口返回的论文元数据（DOI / 标题 / 作者） | ✅ 唯一可进结论者 | DOI / 条目 ID + 文件哈希 |
| **判断 judgment** | 模型生成的检索式、逐篇相关性裁决与理由 | ❌ 仅影响流程走向 | **全额留痕，含被排除项与排除理由** |
| **结论 conclusion** | 排名、统计量 | 只能由确定性程序从事实推导 | 必须绑定事实级证据编号 |

- **关键点**：连"它扔掉了什么、为什么扔"都要记账——使筛选从黑箱变成**可上诉的裁决**。

### D6 复现契约：收窄到"冻结输入之后"
- **决定**：模型筛选结果一旦产生，**立即冻结为输入快照**；此后的复算、验证、重新出报告全部针对该快照。
- **承诺范围**：保证"从冻结快照到结论"逐字节可复现；**不承诺**"模型这次筛了什么"跨次一致。
- **理由**：模型输出不确定，强行承诺全链路可复现等于自欺；这是现实世界 ML 流水线的通行做法。

### D7 人工介入：异常驱动
- **打断条件**（命中任一即停下等人裁决）：
  1. **零命中**：检索式无任何结果
  2. **两腿对不上**：文献腿的论文在 OBELiX 中找不到对应实测数据（DOI 匹配失败）
  3. **命中率反常**：模型判"相关"的比例过高或过低（如 50 篇判 48 篇相关）
  4. **模型自相矛盾**：同一篇论文在两轮筛选里结论相反
- **不打断**：技术性异常（接口超时、网络中断）→ **自动重试 + 降级**，复用现有"重试→降级"机制
- **理由**：本流水线**无任何不可逆副作用**（不写外部系统、不发消息），不需要"危险操作确认"式闸门；全程人工确认会退化为人肉流程。

### D8 受众：作品交付 + 需功能演示
- **决定**：改造的第一驱动是"作为作品交付"，且**必须支持功能演示**。
- **推论**：可演示性是**一等需求**，必须写进设计，不能事后补。

### D9 工程约束
- **决定**：
  1. **守住零第三方依赖**：联网用标准库 `urllib`；OBELiX 用标准库 `csv` 解析 599 行
  2. **保留离线可跑通路径**：快照在手时断网也能跑完全流程
  3. **演示双模式**：*回放模式*（读冻结快照，结果确定、零翻车风险，适合正式答辩）/ *现场真跑*（真联网，惊艳但有风险）
  4. **审计包与复现命令从"副产品"升级为"必须完好"**——它们是演示的正式素材

### D10 交付形态：双轨
- **决定**：两条轨共用同一套 Python 核心与同一套证据账本，区别只在"输入是快照还是现搜"

| | 主线（稳定轨） | 增强线（惊艳轨） |
|---|---|---|
| 依赖 | 无需 AGH / key / 网络 | 需要 AGH + 模型 key + 网络 |
| 输入 | 冻结快照 | 现场真跑 |
| 展示 | **可信性**：一键跑通、逐字节复现、证据可回查 | **智能性**：真在搜、真在判断、异常真会打断 |
| 风险 | 零 | 有 |

- **否决**：AGH 单轨——AGH 安装需**交互式 TTY 人工确认**（`package add` 无 bypass）且需要 key，评委/观众无法一键复现，等于把作品的可验证性押在最难复现的一环上。
- **不变式**：**档 3 的模型判断必须由 AGH 提供**——项目自身不带模型，故增强线不可删除。

## 5. 红线条款修订（必须同步执行）

原措辞："**模型不参与计算与结论生成**"

修订为：

> 模型参与**检索式生成与相关性筛选**，但**不产生任何数值与结论**；模型的全部判断以 `judgment` 级对象全额留痕（含被排除项与理由），不进入结论，可被人工复核与反驳。所有数值均来自公开数据集（OBELiX，附 DOI）与本地确定性计算；复现契约覆盖"冻结快照之后"的全部环节。

这是**把话说准，不是把红线放松**：模型现在确实会影响"分析哪些材料"，隐瞒这一点比修订条款更危险。

## 8. 技术探针实测结果（2026-10-02，闸门已通过）

**结论：D2（OBELiX）与 D3（双腿 + DOI 对接）双双成立，方案继续。**

探针脚本：`tools/probe_obelix.py`（零依赖 · 只读 · 可离线复跑）
数据：`data/external/obelix/all.csv`（官方 `NRC-Mila/OBELiX` main 分支，599 行，112 KB）
完整报告：`tools/probe-report.json`
复现命令：
```bash
python tools/probe_obelix.py --input data/external/obelix/all.csv --doi-sample 10
```

### 8.1 数据可用性（本地分析，离线可复跑）

| 指标 | 实测值 |
|---|---|
| 总行数 | **599** |
| 可用数值行 | **562**（93.82%） |
| 不可用行 | 37 —— **全部是上界记法**（`<1E-10` / `<1E-8`） |
| 主列空值 | 0 |
| 数值写法分布 | 科学计数法 291 / 纯小数 271 / 上界记法 37 |

**关键发现**：可用值**全部来自主列** `Ionic conductivity (S cm-1)`，`IC (Total)` 与 `IC (Bulk)` 两列在本数据集中**全为空**（原始设计中的"数值回落链"在本数据集上无需启用，但保留以备镜像差异）。

### 8.2 DOI 可解析性（联网抽查）

| 指标 | 实测值 |
|---|---|
| DOI 覆盖率 | **100%**（599/599 行均有 DOI） |
| 唯一 DOI 数 | **223** |
| 抽样解析 | 10 个 DOI → **Crossref 10/10、OpenAlex 10/10**（HTTP 200） |
| 另有 close_match DOI | 存在（用于标注结构来自近似匹配而非原论文） |

### 8.3 探针带来的方案修订

1. **列名适配**：官方 CSV 用人类可读表头（`Ionic conductivity (S cm-1)`、`Reduced Composition`），第三方镜像用 snake_case（`ionic_conductivity_s_per_cm`）。**P2 清洗层必须做列名归一**，不能硬编码单一命名。探针脚本已实现该映射（`resolve_columns`）。
2. **`family` 字段语义确认**：实际为**化学族**（43 个取值：NASICON 134、garnet 105、perovskites 68、argyrodites 52、LGPS 36、thio-LISICON 26、sulfides 11…），与原实验的"硫化物/石榴石/薄膜"概念**同源可比**。但原脚本中写死的 4 族稳定性对照表**必须废除**，改为从数据实际取值驱动（或显式声明为可配置权重）。
3. **规模跃升**：排序对象从 **6 行 → 562 行**，"规模"这条价值线首次成立（对应判据 1 的 ≥500 条要求，实测 562 条达标）。
4. **`split` 列不在 all.csv 中**（仅存在于 train/test 分文件），若后续要做"训练/测试"实验需另取文件。
5. **37 条上界值与 33 条空 family 是可复用的真实脏数据**：P2 的清洗步骤从此有真实意义，不再需要人为埋坑。

### 9.2 两处由实测带来的设计修正（重要）

**修正一：D3「两腿 DOI 高重合」假设被否证。**

| 测量 | 结果 |
|---|---|
| 文献腿（4 检索式 × 2 来源） | 373 篇 |
| OBELiX 数据腿 | 222 篇 |
| **交集** | **8 篇（2.1%）** |

文献腿给的是**话题全景**（综述、近年高影响论文），数据腿是**一个特定实测数据集的
来源论文**，天然只少量重叠。若不测量就写规则，会把正常行为误报为异常，
进而被迫放宽容差、使告警失效。

→ **异常规则据此修正**：低对接率**只作指标报告**，只有"交集为零"才判定异常。
已加回归用例 `test_low_join_rate_is_NOT_anomaly` 锁死该判断。
另发现 85 条 `.s001` 支撑信息 DOI（非主论文），单独识别并排除出可对接集合。

**修正二：D10 的模型调用路径需重新表述。**

原设想是 Python 通过 AGH 取模型（打印模式或模型 API）。实测**两条路都不可用**：

| 尝试 | 结果 |
|---|---|
| `agh -p "<prompt>"`（daemon 未启动） | 260s 超时 |

→ **D10 修正为**：设计内的主路径是**AGH 会话内判断** ——

**标准 OpenAI 兼容端点**（环境变量 `PAPER_AGENT_LLM_BASE_URL` / `_MODEL` / `_API_KEY`）。

### 9.5 真实模型对比结论（已完成，2026-10-02）

**端点为标准 OpenAI 兼容服务**（`PAPER_AGENT_LLM_BASE_URL` / `_MODEL` / `_API_KEY`；

复现命令：

```bash

export PAPER_AGENT_LLM_API_KEY=<your key>
python tools/compare_judges.py --goal "sulfide solid electrolyte ionic conductivity ranking"
```

### 结果

| 观测面 | 规则式基线 | 模型（DeepSeek） |
|---|---|---|
| 生成检索式 | 2 条（`sulfide solid electrolyte ionic conductivity`、`sulfide solid`） | **4 条**（含 `argyrodite sulfide electrolyte ionic conductivity`、`Li6PS5Cl ionic conductivity`） |
| 判定为相关的族 | 6 / 42 | **7 / 42** |
| 差异 | — | **1 个族翻转**：`Chalcogenidotetrelates`（规则式 excluded → 模型 relevant） |

**判决（按反判据）：`model_matters`，退出码 0。**

### 如实评估幅度（不要过度解读）

反判据只回答"是否改变"，**没回答"改变得多不多"**。就本次实测：

- **范围裁决的差异很小**：42 个族里只差 1 个。若只看这一面，很容易得出
  "模型接近装饰品"的印象。
- **检索式的差异更实质**：模型给出的 4 条里有 2 条是**材料特异**的
  （指名 argyrodite 与 Li6PS5Cl），规则式只会做"去停用词 + 取前 2 个词"，
  永远产不出这种检索式。检索式质量直接决定文献腿的召回。
- **那 1 个翻转恰好暴露了规则式的盲点**：`Chalcogenidotetrelates`
  （硫属元素 + 碳族元素的化合物）**本质就是硫系/硒系化学**，
  但家族名里没有一个字面 "sulfide"，字面匹配规则必然漏掉它。
  模型的裁决在这一项上**比规则式更正确**。

**结论**：模型在本任务中不是装饰品，但其增量价值主要体现在
**检索式质量**与**对字面规则盲区的补偿**上，而不是"大范围改变结论"。
若后续要放大模型价值，方向应是让模型参与**更难判断的对象**
（例如逐篇论文的相关性，而非 42 个族的粗粒度归类）。

## 10. 一句话总结

本次改造的实质，是把"人工喂数据 → 程序算数"换成"**Agent 去真实世界取数据、做筛选判断、自己记账**"；用一个克制的信任模型（事实/判断/结论三级分离 + 冻结快照 + 异常打断）来容纳"模型判断不可复现"这个绕不开的代价；交付上以 **Python 主线保可验证性**、以 **AGH 增强线保智能性**，让演示既翻不了车、又能证明它不再是计算器。
